# هامون — پایه قابل توسعه اپ نوبت‌دهی پزشک

این پروژه یک پایه Flutter برای اپ اندرویدی نوبت‌دهی است. ساختار آن عمداً بر اساس featureها و قراردادهای repository جدا شده تا بعداً افزودن امکانات، جایگزینی داده‌های نمونه با API و توسعه نقش‌ها ساده‌تر باشد.

## امکانات فعلی
- صفحه اصلی فارسی و راست‌چین
- مسیرهای جداگانه برای ورود، فهرست پزشکان و نوبت‌ها
- جست‌وجوی نمونه بر اساس نام پزشک، تخصص و شهر
- ورود نمایشی با شماره موبایل و کد ثابت `123456`
- نگهداری توکن نمایشی در secure storage
- لایه‌های domain/data/presentation برای ویژگی‌های اصلی
- پیکربندی آدرس API از طریق `--dart-define`

## مهم: این هنوز نسخه تولیدی نیست
- کد `123456` صرفاً برای دموی محلی است و پیامک واقعی ارسال نمی‌شود.
- پزشکان و نوبت‌ها داده‌های ساختگی هستند.
- رزرو نوبت واقعی پیاده‌سازی نشده است؛ جلوگیری از رزرو هم‌زمان یک زمان باید در بک‌اند انجام شود.
- قبل از انتشار، باید احراز هویت سمت سرور، نقش‌ها و مجوزها، محدودسازی درخواست‌ها، ثبت رخدادهای امنیتی، سیاست حریم خصوصی و الزامات قانونی داده‌های سلامت بررسی شوند.
- از اطلاعات واقعی بیماران در دموی فعلی استفاده نکنید.

## پیش‌نیاز
Flutter SDK و Android Studio یا Android SDK نصب باشد.

## اجرا
از پوشه پروژه:
```bash
flutter pub get
flutter run
```

## تنظیم آدرس بک‌اند در آینده
```bash
flutter run --dart-define=API_BASE_URL=https://your-api.example/api
```

## ساخت APK
```bash
flutter build apk --release
```
خروجی معمولاً در مسیر `build/app/outputs/flutter-apk/app-release.apk` ساخته می‌شود.

## ساختار
```text
lib/
  app/                 # پوسته اپ و مسیرها
  core/                # تنظیمات، شبکه، خطاها و ویجت‌های مشترک
  features/
    auth/              # قرارداد ورود، پیاده‌سازی نمونه، صفحه ورود
    doctors/           # مدل و فهرست پزشکان
    appointments/      # مدل و قرارداد نوبت‌ها
    home/              # صفحه اصلی
```

## معماری توسعه
- UI فقط با repositoryها کار کند، نه مستقیماً با API.
- برای هر قابلیت جدید یک پوشه زیر `features/` اضافه کنید.
- پیاده‌سازی نمونه را با پیاده‌سازی API عوض کنید، بدون بازنویسی صفحه‌ها.
- بک‌اند باید حداقل موجودیت‌های `users`, `doctors`, `clinics`, `doctor_schedules`, `appointments` و کنترل دسترسی داشته باشد.
- رزرو نوبت باید تراکنشی/اتمی باشد تا دو نفر یک اسلات را هم‌زمان نگیرند.
